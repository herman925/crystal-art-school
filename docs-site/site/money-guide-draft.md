# Course prices, coupons, sales and course access

> **Draft — not approved for live use.** These instructions must be checked against the final reviewed screens before access is handed over. Do not use this draft as permission to make live changes.

## Quick safety checklist

Before every money or access change:

1. Check the exact course, student or order. A similar name is not enough.
2. Write down what is there now and what should change. Use agreed prices, not the example numbers below.
3. Use one change tab at a time. Do not ask someone else to change the same item while your confirmation is open.
4. Read the review page before confirming. Opening a form is not the same as saving it.
5. Click the final confirmation once and wait. If the result disappears, check a fresh list before doing anything else; a missing response does not prove nothing happened.
6. Check the saved result. If it is unexpected or uncertain, stop and ask Herman. Do not make a second money change to repair the first.

Never share a confirmation link, password, card details or another person's account. A screenshot for support should show only the information needed to identify the problem.

## Choose the right tool

| What you need | Use | What it does not do |
|---|---|---|
| Set a new draft's first paid price | **Course prices → Set first price** | Does not publish the course |
| Change a course's regular or sale price | **Course prices → Review change** | Does not rewrite existing orders or issue refunds |
| Offer a code for future checkout | **Coupons** | Does not refund an earlier purchase |
| Review an order or correct an allowed pending status | **Sales** | Does not collect a payment or issue a refund |
| Give or remove one student's course access | **Course access** | Does not change an order or a payment |

A course's price, an order's status, a payment's status and a student's access are separate things. Do not change one simply to make another look right.

## Prices: understand Regular and Sale

**Regular** is the normal price. **Sale** is optional and must be a positive amount lower than Regular.

- Enter numbers such as `60` or `60.50`, with at most two decimal places.
- Do not enter `£`, commas, words or percentages into the amount boxes.
- Regular must be greater than zero.
- For no sale, leave Sale completely empty. Do not type `0`, `none`, a dash or the word `empty`.
- An old stored zero sale may be displayed as no sale. That does not make a newly entered zero sale valid.
- The agreed currency is GBP (£). If the screen appears to use a different currency, stop and ask Herman rather than changing global settings.

Example amounts in this guide are not approved prices for any real course.

A course price is not a promise of the amount received in a bank account. This guide does not set provider fees, settlement currency, payout timing or tax treatment. Price changes do not alter those arrangements.

## A new paid course: save a draft before setting its first price

**The sequence is: create → prepare content → save as draft → confirm first price → reload the same course → publish only when ready.**

### Prepare the draft

1. Open **Content hub → Add course** once and wait for the course builder.
2. Give the course a distinct title. Do not leave several identically named drafts and guess between them.
3. Prepare its description, images, topics, lessons and lesson order. Save individual lesson changes using their own save controls.
4. Save the course content as a draft. Do not assume moving to another page saves unfinished work.
5. Keep that saved course tab open and open **Course prices** separately.

If course creation stalls or reports an error, stop. A draft may already exist. Repeatedly clicking Add course can create duplicates.

### Set the first price

1. Find the exact new draft in **Course prices**.
2. Use its **Set first price** row. If unexpected current amounts appear, stop and check the course rather than assuming it is unpriced.
3. Enter the agreed Regular and optional Sale amounts, then click **Set first price**.
4. Check the title and the **Now / New** table.
5. Type **Current regular**, **Current sale**, **New regular** and **New sale** from that table. Leave genuinely empty/no-sale amounts empty; do not invent zero values.
6. Click **Save the new prices** once.
7. Continue only after a clear saved result and a fresh check of both amounts.

For an unpriced draft becoming £60 with no sale: New regular is `60`; New sale is empty. If both Now amounts are genuinely empty, both Current fields are empty too.

### Publication is separate

1. Return to the same saved course tab. Preserve any unsaved text before refreshing.
2. Reload the builder so it reads the confirmed price rather than stale earlier values.
3. Check the course title, lessons, images, displayed price and agreed publication timing.
4. Publish only when those checks are complete. Then check the final course status and public information page.
5. Do not make the paid lessons publicly accessible or switch the course to free to bypass a refusal.

A saved price is not a published course. A public course-information page is not permission to make the paid lessons public.

If the price is saved but publication remains blocked, keep the course as a draft and ask Herman. Do not set the first price again as a repair.

## An existing paid course: change its price through Course prices

1. Open **Content hub → Course prices** and identify the right course.
2. Read its current amounts. Enter the complete proposed Regular and Sale; clear Sale if the sale should end.
3. Click **Review change**. This prepares a proposal; it does not yet save the amounts.
4. Check the course and both **Now / New** rows.
5. Re-enter the four confirmation fields carefully. Current means the old amount, not the proposed amount.
6. Click **Save the new prices** once. Check the saved message and both amounts in a fresh list.
7. Reload any already-open course builder before its next content save so it does not submit stale prices.

Example: Now is Regular £60 / Sale £45, and New is Regular £68 / Sale £52. Type Current regular `60`, Current sale `45`, New regular `68`, New sale `52`.

To end that sale later, propose Regular `68` and empty Sale. Confirm Current regular `68`, Current sale `52`, New regular `68`, and empty New sale.

### Timing and limits

- A confirmation expires after 10 minutes and belongs to the signed-in account. That is not the duration of a sale.
- An existing free or unknown-type course cannot be converted through this price screen. Ask Herman if the intended course is missing.
- Do not use the ordinary builder save as a price-change route.
- For an already published course, treat a successful price save as a real change now, not a future announcement.
- This tool does not schedule a sale end. Agree when to remove the sale before advertising it.
- Existing orders are not rewritten. Do not promise that an already-open cart, checkout or payment session immediately uses a newly saved price; ask Herman about the specific case.

### Price problems: start fresh or stop

| What happened | What to do |
|---|---|
| Invalid number, too many decimals, or Sale not below Regular | Correct the proposal before requesting a new review |
| Typed amounts do not match | Check a fresh price list, then prepare a new confirmation |
| Confirmation expired or already used | Check whether the intended amounts were already saved before starting again |
| Current price changed while you were deciding | Check the new current state; agree which amount is intended before a new proposal |
| Another price change is processing | Stop clicking; recheck after it finishes; ask Herman if it keeps returning |
| Audit/record-keeping failure | Stop price changes and ask Herman |
| Previous price pair restored after a failed write | Treat the proposal as not saved; stop and ask Herman before another attempt |
| Change and restoration could not be verified | Stop all price/course-save attempts immediately and contact Herman |
| First price saved but publication still blocked | Do not set the price again; keep the draft and contact Herman |
| Builder says to change prices through Course prices | Preserve unsaved text, use the price process, then reload the saved builder |

Closing a tab does not remove a published price. Do not type the old amounts back as an unreviewed repair.

## Coupons: check the effect before sharing a code

**A coupon changes the checkout offer for people who use it. It does not correct a past order.**

The current coupon screen supports code coupons for all courses. Do not assume it limits a code to one course, one recipient or a bundle.

### Create a coupon

1. Open **Content hub → Coupons** and choose the new-coupon form.
2. Give it a recognisable title and a distinct code. Codes use 3–40 letters, numbers, dashes or underscores.
3. Choose a percentage or fixed-amount discount. A percentage cannot exceed 100.
4. Enter the amount as a number above zero with at most two decimals. A percentage `20` means 20%; a fixed amount `20` means an amount, not 20%.
5. Set the start date and, if wanted, an expiry date on or after it. The form uses `YYYY-MM-DD`.
6. Check total-use and per-user limits. Blank means no limit, not zero uses. Use a positive whole number for a limit.
7. Read the whole form again before saving, especially discount type, amount, dates and limits.
8. For a 100% percentage coupon, tick the explicit free-course warning only if that is intended.
9. Save once, then check the fresh coupon list before distributing the code.

A 100% code makes the course free for anyone who successfully uses it within its restrictions. A large fixed discount can also remove the amount due on a lower-priced course. Do not rely on the absence of a warning checkbox as proof that a discount is small.

Do not promise that a date takes effect at a particular student's local midnight. If an advertised deadline needs an exact timezone or checkout cut-off, ask Herman to verify it first.

### Edit, deactivate or delete

- Check the exact code before editing. Changes affect the coupon's future use; they do not refund earlier purchases.
- A used coupon's code cannot be renamed, and a used coupon cannot be deleted. Deactivate it instead if it must stop being available.
- Deactivation is not a refund and does not by itself remove course access already granted.
- Activation is not proof that dates, usage limits or other checkout eligibility will permit every attempted use.
- Do not keep using an earlier edit tab after someone else changes the coupon.

If creation cannot be verified, do **not** submit again. Refresh the list without editing and ask Herman whether a coupon was already created. An uncertain save must not become two offers through repeated clicking.

## Sales: order status is not proof of payment

**Use payment evidence, not an order-status label, to decide whether money arrived. Never mark an order completed simply to make a payment problem disappear.**

1. Open **Content hub → Sales**.
2. Find the order by order number, course, status or date range. Check the student login and course together.
3. Read **Order status** and **Payment status** separately. If either is unexpected, ask Herman before changing it.
4. Only pending orders offer the supported manual changes: completed or cancelled.
5. Select the intended change and read the confirmation page. No change is made merely by opening that page.
6. Confirm once only after checking the exact student, course and consequences.
7. Check the result in a fresh list. If the response is uncertain, stop rather than repeating the submission.

### Completing a pending order

Completing it gives course access. It does not collect money, mark a payment paid or establish that funds reached a bank.

If no payment is recorded, the screen warns:

> No payment is recorded for this order. Completing it gives the student access for free.

The separate checkbox is deliberate. Do not tick it unless giving access without recorded payment is the agreed action.

If payment changes while a confirmation is open, review the order again. Do not reuse or modify the old confirmation to get past that warning.

### Cancelling a pending order

This is not a refund. It does not reverse a payment. It does not remove independent course access from another completed purchase.

This screen does not cancel completed orders. Do not create another order or change payment settings to work around that restriction. If access needs correction, use the separate Course access process only after the intended action is agreed.

### Failure messages

- An unsupported course/student/order is a reason to stop and ask Herman, not to manufacture a replacement order.
- If the change cannot be recorded or saved, do not treat it as completed.
- If restoration could not be verified, stop immediately and send Herman the order number, time and exact message. Partial state may need checking.
- A success message is not a promise that a receipt or enrolment email was sent. Do not resend a money action to try to trigger an email.

## Sales exports and totals

**Exported student information must be kept private. Export only what you need.**

1. Apply the intended Sales filters and check the visible orders first.
2. Choose **Download CSV of this list**.
3. Open the file carefully and check that the filter range and columns are what you expected.
4. Store it securely. Do not upload it to public sharing or analysis tools, and do not send the full file when only one order needs support.

The actual columns are order ID, date, student login, course, order status, payment status and amount. Names and email addresses are not included by this export. Text starting like a spreadsheet formula may carry a protective leading apostrophe; do not strip it simply to make the cell look different.

The list/export is limited to 200 matching orders. It is not a complete accounting export when more orders match. Ask Herman if you need a complete reconciliation.

Monthly totals count completed orders, not bank deposits. Course totals use item prices before tax and coupons. Without a date filter, the totals use a recent 12-month window. Do not treat these figures as provider settlement, profit, tax records or refund reconciliation.

## Course access: change access without changing money

**Use this only for an agreed one-off access correction. It does not charge, refund, create an order or change an order's status.**

1. Open **Content hub → Course access**.
2. Enter the existing student's login or email. This tool does not create a student account. Staff accounts are not valid targets.
3. Choose the correct published course and **Add access** or **Remove access**.
4. Click **Review change**.
5. Check the student's name/email, course and current access. An email on this confirmation is private; do not circulate it unnecessarily.
6. Read the warning, then use **Confirm give access** or **Confirm remove access** once only if that is intended.
7. Check the result. If the student already has access or has no active access, do not force another action.

Adding access gives the student the course without creating or correcting a payment record. Removing access removes that student's access to the selected course, including access represented by existing enrolment rows; it does not issue a refund or cancel a paid order.

Do not use Remove access as an automatic refund/dispute policy. Ask Herman to check the particular order and intended access decision. A later legitimate payment/enrolment event may need separate investigation rather than another manual correction.

If the access state changes after the review page opens, start from a fresh review. If the screen reports an audit failure, save failure or unverified restoration, stop and contact Herman. Do not change an order to repair an access error.

## What to send Herman

Send the course title, order number where relevant, approximate time, exact message, and intended old/new amounts or access change. Say whether you pressed the final confirmation and whether a saved message appeared.

For a lost response, say that the result is unknown. Do not report “nothing happened” unless the fresh state has been checked. Never send a password, full card details or a reusable sign-in/confirmation link.
