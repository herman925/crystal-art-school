# Money and access troubleshooting

> **Draft — awaiting final-screen and behaviour verification. Not approved for live use.**

## Quick checklist

Stop clicking. Read the exact message. Check a fresh list without editing. If saved state is uncertain, contact Herman before another attempt. Never use a different money or access action as a repair.

## Price warnings

| What happened | What to do |
|---|---|
| Invalid number, too many decimals, Sale not below Regular | Correct the proposal before requesting a new review |
| Typed amounts do not match | Read a fresh price list and prepare a new confirmation |
| Confirmation expired or already used | Check whether the intended price was already saved before starting again |
| Current amounts changed while deciding | Check the new state and agree which price is intended before a new proposal |
| Another change is processing | Stop clicking; recheck after it finishes; ask Herman if it persists |
| Audit/record-keeping failure | Stop price changes and contact Herman |
| Previous price pair restored after a failed write | Treat the proposal as not saved; ask Herman before another attempt |
| Change and restoration could not be verified | Stop all price/course-save attempts immediately and contact Herman |
| First price saved but publication still blocked | Keep the draft; do not set its first price again; contact Herman |
| Builder directs prices to Course prices | Preserve unsaved text, use the price process, then reload the saved builder |

Closing a tab does not remove a published price. Manually typing the old amounts back is another money change, not a safe repair.

## Coupon, Sales and Course access warnings

- **Coupon creation cannot be verified:** do not submit again. Check the fresh list and ask Herman whether the coupon already exists. Do not delete an uncertain row as a repair.
- **Used coupon cannot be renamed/deleted:** check the intended coupon; deactivate it if the agreed offer must end. Do not create a replacement offer without agreeing it.
- **Sales confirmation no longer matches payment:** leave it and review the fresh order. Do not modify the confirmation or payment status to force it through.
- **Unsupported student/course/order:** check the intended item and ask Herman. Do not make a replacement account/order/course or use administrator credentials to bypass the refusal.
- **Access changed after review:** request a fresh review only after the current state is clear.
- **Audit/database/save failure:** do not treat the change as completed. Stop and ask Herman.
- **Restoration could not be verified:** stop immediately. Partial state may need checking; do not submit a compensating change yourself.
- **No email appeared:** a saved result is not a delivery promise. Do not repeat the order/access action to trigger mail.

## Lost response or stalled browser

Do not double-click, refresh a submitted confirmation or automatically resubmit. Open a fresh list without editing and note the saved state. If you cannot confidently tell whether the first request completed, contact Herman before another proposal or publication.

A missing response does not prove the server did nothing. An “already used” price confirmation may follow an earlier successful save.

## What to send Herman

Send:

1. Course title and whether it is a new draft or already published.
2. Order number or coupon code where relevant, and only the student information needed to identify the issue.
3. Approximate time and what you clicked immediately before the problem.
4. Exact message or a carefully cropped screenshot.
5. Current/old and intended new prices, or intended access change.
6. Whether you pressed final confirmation and whether any saved message appeared.

For a lost response, say the result is unknown, not “nothing happened”. Never send passwords, full card details, another person's sign-in details or a reusable confirmation link.
