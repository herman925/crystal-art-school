# If a price, order or access change is unclear

Stop clicking, keep the exact message, and check a fresh list **without changing anything**.
A missing response does not prove nothing happened.

| Message or situation | Your next step |
|---|---|
| Price format is invalid or Sale is not below Regular | Correct the proposal before requesting review |
| Current price changed, or confirmation expired/was used | Check the fresh prices; prepare a new review only after the saved state is clear |
| Another change is processing | Wait and recheck; ask the site administrator if it persists |
| Change could not be recorded or saved | Stop and send the site administrator the message |
| Previous values restored after a failed save | Treat the proposal as not saved; ask the site administrator before retrying |
| Change/restoration could not be verified | Stop all edits to that course/order/access until the site administrator checks it |
| First price saved but publishing is blocked | Keep the draft; do not set the price again |
| Coupon creation is uncertain | Check whether it exists; do not submit again |
| Used coupon cannot be renamed/deleted | Deactivate the intended code if that is the agreed action |
| Payment/access changed while confirmation was open | Read a fresh review; do not modify the old confirmation |
| No email appeared | Ask the site administrator to check delivery; do not repeat the order/access action to send mail |

Do not type old prices back, create another order or use a different access/payment action
as a repair. Those are new changes, not an undo button.

Send the site administrator the course/order/code, intended change, approximate time, exact message and
whether you pressed final confirmation. Include only the student details needed to find
the case. Do not send passwords, card details or confirmation links.
