# Sales

> **Draft — awaiting final screen checks and handover. Not approved for live use.**

## Quick checklist

Check order number, student login, course, order status and payment status separately. Read the access consequence before confirming. Confirm once, check a fresh list, and stop if the result is uncertain.

**Rule: order status is not proof that money arrived. Never complete an order simply to make a payment problem disappear.**

## Find and review an order

1. Open **Content hub → Sales**.
2. Find the order by number, course, status or date range. Check the login and course together.
3. Read **Order status** and **Payment status** separately. Ask the webmaster if either is unexpected.
4. Only pending orders offer the supported changes: completed or cancelled.
5. Select the intended change and read the confirmation. Opening it makes no change.
6. Confirm once only after checking the student, course and consequences.
7. Check the result in a fresh list. Do not repeat a submission whose result is unknown.

## Completing a pending order

Completion gives course access. It does not collect money, mark a payment paid or prove funds reached a bank.

If no payment is recorded, the screen warns:

> No payment is recorded for this order. Completing it gives the student access for free.

Tick the separate checkbox only if giving access without recorded payment is intended. If payment changes while confirmation is open, review the order again. Do not reuse or modify the old confirmation to get past a warning.

## Cancelling a pending order

This is not a refund and does not reverse a payment. It does not remove independent course access from another completed purchase.

The screen does not cancel completed orders. Do not create another order or alter payment settings to work around that restriction. Use [Course access](./course-access-draft.md) only for an agreed access correction, not as an automatic substitute for payment handling.

## Export the filtered list

**Student information in exports must be kept private. Export only what you need.**

1. Apply the intended filters and check the visible orders.
2. Choose **Download CSV of this list**.
3. Check the exported range and columns before using the file.
4. Store it securely; do not upload it to public sharing or analysis services. Send only the necessary order information for support.

Columns: order ID, date, student login, course, order status, payment status and amount. This export does not include names or email addresses. Formula-like text may deliberately have a protective leading apostrophe. Keep protective prefixes in place; removing them can undo the spreadsheet-safety protection.

The list/export is capped at 200 matching orders, so it is not a complete accounting export when more match. Ask the webmaster if you need complete reconciliation.

## Read totals cautiously

Monthly totals count completed orders, not bank deposits. Course totals use item prices before tax and coupons. Without date filters, totals use a recent 12-month window.

These are not provider settlement, profit, tax records or refund reconciliation. A completed order is not a receipt-delivery confirmation.

## If something goes wrong

If recovery or restoration is uncertain, **stop and contact the webmaster immediately**. Do not assume that nothing changed, submit the action again, or make a second order/access change to repair it. A partial change may need checking.

For other unsupported-course/student/order, audit or missing-result warnings, follow [Troubleshooting](./money-help-draft.md), not repeated clicks. A success message does not promise a receipt or enrolment email was sent; do not repeat a money action to trigger mail.
